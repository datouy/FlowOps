# 云策 YunCe · 项目升级优化提示词（2026-11-25）

> 定位：这份提示词用于让 AI 以「产品负责人 + 技术架构师 + 全栈工程师 + 质量负责人 + 设计负责人」的多重角色，自主完成云策 FlowOps 的项目升级。它不是步骤清单，而是「目标 + 约束 + 方法 + 验收」，给 AI 留出自主规划与执行空间。
>
> 使用前提：AI 拥有仓库读取、测试执行、代码修改权限。
> 暂停原则：仅当涉及资金、数据删除、正式发布、外部账号授权，或确实无法从项目资料判断的关键决策时才暂停并集中询问；其余自主推进、用证据说话。

## 一、最终目标（先定向，不要套步骤）

把云策 YunCe 从「代码层已闭环、自动测试已通过」升级到「可证明的工程与产品双达标」：

- 工程达标：安全、可靠性、可维护性、可观测性、测试有效性、文档一致性，全部有证据。
- 产品达标：真实平台发布、真实登录、强杀恢复、Docker split、旧库迁移、容量基线，全部有 E3/E4 证据，或形成明确的「待外部资源」清单与责任人。

可测量的验收基线（候选值，需按实际规模复核，不得机械套用）：

- 管理面月可用性 ≥ 99.5%；数据 RPO ≤ 15 分钟、RTO ≤ 2 小时。
- 后端全量测试、前端 lint/test/build 在最终提交上重跑通过并保留输出。
- 真实三平台（抖音/小红书/视频号）各至少一条私密/草稿发布 + 远端终态回查 + 重启不重复发布。
- 无明文密钥进入仓库或脚本；审计保留 ≥ 180 天。

## 二、项目事实（必须自行复核，不要照抄文档）

- 技术栈：Flask + Waitress、Vue 3 + Element Plus + Vite、Playwright/Patchright、SQLite。
- 已实现：四角色 RBAC、账号 scope、任务队列/租约、执行器分离、Chromium 分片、健康探针、Prometheus 指标、备份恢复、实名会话 + MFA、人员离岗联锁。
- 基线（2026-11-25）：后端 746 passed、Ruff、前端 lint/test/build 均通过。
- 已知边界：单机多进程架构；真实平台发布/登录/强杀/Docker split/旧库迁移/性能基线仍未验证。

## 三、约束与暂停边界

- 不删除生产数据、不轮换真实凭据、不执行真实公开发布、不强杀生产进程、不对外发消息——这些必须先给出可审查方案与回滚，再暂停询问。
- 不改动主发布状态机、幂等键、风控降速、凭据加密的核心语义；优化优先走「入口 + 旁路 + 文档」。
- 缺失的关键约束（上线日期、预算、人力、身份系统、合规要求）用「待确认」保留，不编造。

## 四、三步方法论落地

### 第一步：定向（从最终目标反推，不是补丁式）

1. 一段话复述最终目标、业务边界、可测量定义。
2. 端到端业务域、依赖、角色、数据流、外部平台、部署链路、运维责任。
3. 主动补遗漏：身份生命周期、职责分离、旧库迁移、备份恢复、密钥轮换、平台风控、可观测性、容量、回滚、人工兜底、事故响应。
4. 三档范围（最小升级 / 稳健升级 / 规模扩展）+ 推荐与理由。
5. WBS、关键路径、里程碑、验收门。
6. 明确哪些必须由人工、真实账号、域名或企业基础设施完成。

### 第二步：深挖（不接受表面结论）

- 建立证据台账，逐项标记：已验证 / 仅代码 / 仅自动测试 / 受控环境 / 真实生产 / 未验证 / 被推翻。
- 检查代码与文档一致性（是否存在「代码已写但路由未注册」「文档已写但代码未做」「测试通过但路径未覆盖」）。
- 复算关键数据、核对样本量、主动寻找能推翻当前判断的反证。
- 列出所需原始资料、方法、工具，并说明作用、可信度、缺失影响与替代方案。

### 第三步：借力（把成熟方法落到交付物）

借用并落地以下领域方法，不允许空泛建议：

- 项目管理：WBS、RACI、关键路径、发布门。
- 风险工程：FMEA 风险登记册（触发/概率/影响/预警/负责人/缓解）。
- SRE：SLI/SLO、容量模型、故障演练、runbook。
- 安全：威胁建模、最小权限、默认拒绝、密钥生命周期。
- 质量门：真实 canary、缺陷逃逸矩阵、根因分析。
- 电商履约：状态机、幂等、对账、人工复核队列。
- 财务风控：单次发布成本、AI 成本、预算阈值、异常成本告警。
- 应急管理：检查单、双人复核、回滚/降级 SOP。

## 五、验收与证据等级

| 等级 | 定义 | 可支撑结论 |
| --- | --- | --- |
| E0 | 只有文档/注释 | 仅说明有人提出过 |
| E1 | 静态代码/配置检查 | 代码路径存在 |
| E2 | 自动测试/静态分析通过 | 被测范围当前通过 |
| E3 | staging/隔离环境实际运行 | 受控环境行为 |
| E4 | 真实生产数据 + 真实平台 | 生产可用 |

权限/任务恢复/备份恢复/迁移 ≥ E3；真实平台发布/登录/终态/业务接受 ≥ E4。

完成标准：不得把「文件存在、单测通过、Mock 成功、上传器返回成功、页面提示提交成功、文档写了已支持」当作生产完成。

9. 风险登记册。
10. 待确认决策与缺失材料。
